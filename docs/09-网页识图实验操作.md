# 网页 GPT 识图实验

2026-09-21。本轮只验收固定合成图片经 MCP 进入网页模型的能力。

当前进度：9 项本地自动测试通过，a/b 图片已生成。用户已在网页插件页刷新，并报告看到了 vision_probe。在线认证复验期间曾出现终端与服务状态不一致，尚未取得在线图片字节校验成功记录；以接下来的实际网页调用为准。模型识图尚未验收。

## 本地准备

已经新增 vision_probe(sample_id)，支持 a、b、missing。a/b 是 960×640 PNG，每张包含随机六位码与四个不同颜色/形状的图形；missing 故意返回错误且不含图片。工具只返回样本编号、MIME、长度、哈希以及 image 内容块，不返回答案、OCR 或图片路径。

生成器：scripts/prepare-vision-probe.py，使用本地 Pillow；若样本已存在则拒绝覆盖。样本及 answers.json 存在 Bridge 配置的 state/vision-probe 下；不要把答案或图片提前发给网页 GPT。答案文件不由 vision_probe 暴露；现有命令工具有账户权限，因此测试时必须禁止其他工具，工具记录中如出现读取答案/源码/执行 OCR，应判为实验受到污染。

自动测试：npm test。在线本地验证：node scripts/verify-vision-probe.mjs，验证实际运行 Bridge 返回的两张 PNG 与磁盘字节一致，以及 missing 不返回图片。报告保存在 state/vision-probe/local-verification.json。这不等于网页模型识图通过。

## 用户在网页端操作

1. 保持电脑、Bridge 和本地网络代理运行。
2. 在 ChatGPT 已连接的 X14-Plus Project Bridge 应用管理中刷新/重新扫描工具列表，确认新增 vision_probe。具体按钮以页面为准，无需新建 Tunnel 或重新配置密钥。
3. 新开一个对话，启用该应用，记录所选模型。不要粘贴此前讨论、图片或答案。
4. 粘贴下方提示词，保留每次工具调用的名称、参数、返回/错误和模型回答。若缺少工具，先解决工具刷新，不要让 GPT 改用命令读图。
5. 把完整回答与工具记录发回本地任务，由本地答案评分。不要先告诉网页正确答案再要求它修改。

## 主实验提示词

请进行一次 MCP 图片输入测试。只允许调用 X14-Plus Project Bridge 的 vision_probe，不调用项目摘要、文件读取、命令执行、OCR、浏览器或其他工具，不读取源码或答案文件。

如果你的可用工具中没有 vision_probe，停止并报告“工具未发现”，不要自行推测接口或改用其他工具。

请依次调用 vision_probe，sample_id 分别为 a、b、missing；每次调用后先完成该样本回答，再继续下一个。

对每个样本：
1. 写出调用参数，并说明是否实际获得可感知的图片；如果只能看到文本、元数据或错误，就明确说明。
2. 仅依据本次收到的图片，抄写顶部字符码，并按左上、右上、左下、右下列出图形的颜色和形状。
3. 看不清的字段写“不确定”。如果没有图片，所有视觉字段写“无法判断”，不要套用其他样本内容。
4. 不要将“工具调用成功”或“出现图片链接”当作已经看见图片的证据。

最后汇总三次调用的观察结果。不要自行宣布验收通过，正确性由本地对照答案判定。

## 判定与排查

- a/b 每张共 9 项：六位码整串计 1 项，四个位置的颜色及形状各 1 项。两张 18 项全对、missing 明确无法判断且没有其他读取工具，记为“固定样本基础识图通过”。颜色允许对应的中英文常用名称，不苛求词形。
- 如果形状/颜色明显正确但码有错，记为部分通过，区分文字辨认与图像通路；不立即判整个链路失败。
- 如果有 image 内容而模型声明看不到，保留记录；需要定位宿主如何呈现图片，不能仅靠本地 HTTP 成功排除宿主问题。
- 工具未发现：优先刷新工具列表/新对话；调用超时：检查 Bridge/Tunnel；FIXTURE_UNAVAILABLE：本地样本缺失；missing 的 CONTROL_NO_IMAGE 是预期对照结果。
- 第一轮失败后再做手动上传对照：在另一个新对话中用同一模型直接上传同一张本地 PNG，问相同问题。若手动上传可识别而 MCP 不可识别，证据指向 MCP 到宿主的图片输入路径。不能把手动上传成功记作 MCP 成功。
- 第一轮成功后，另开干净对话反序 b/a 复测；之后才扩展高清小字、裁剪、PDF 页、远端图片和大图。当前结果不代表任意图片或文件均可传输。

# 网页版接入与日常使用

2026-09-21 修订：启动入口已改为 Windows 任务，并集成 SSH 转发检查。最新网页代理复测返回 HTTP 200；当前操作以 [项目全貌与运行维护](06-项目全貌与运行维护.md) 为准，完整验收边界见 [交接记录](07-交接记录与Git维护.md)。本文下面保留账号接入步骤和早期现场说明。

本地服务、SSH 工具、OpenAI 私有 Tunnel 和 ChatGPT 私有应用已经接通。2026-09-21 已从 ChatGPT 网页真实调用 `bridge_status` 与 `list_projects`，返回机器 `X14-Plus` 和三个配置项目。请不要把 API key 发进聊天。

## 第一步：确认 ChatGPT 开发者模式

1. 在浏览器登录你准备使用的个人 ChatGPT 账号。
2. 打开设置，查看“安全与登录”中的“开发者模式”；若当前界面将它放在“应用 / Apps → 高级设置”，也检查那里。
3. 开启开发者模式，打开 [ChatGPT 插件页面](https://chatgpt.com/plugins) 或设置中的应用连接入口。
4. 找到“创建 / Create”或加号，查看连接类型里是否有 **Tunnel**。

界面文字和账号开放情况可能不同。如果没有入口，告诉助手页面上实际显示的选项即可。Plus/Pro 名称本身不能代替账号入口实测。

## 第二步：创建官方隧道

1. 用同一账号打开 [OpenAI Platform 隧道设置](https://platform.openai.com/settings/organization/tunnels)。首次使用 Platform 可能需要先完成个人组织初始化。
2. 创建隧道，名称填 **X14-Plus Project Bridge**。
3. 将其关联到你自己的 Platform organization 和目标 ChatGPT workspace；仅关联 Platform 不一定会在 ChatGPT 出现。
4. 复制生成的 `tunnel_...` ID。它不是 API key，可以提供给助手定位问题。
5. 如果显示无权限，记录实际提示。创建需要 Tunnels Read + Manage；运行和选择需要 Read + Use。不要为了绕过缺失权限创建无认证公网入口。

## 第三步：生成运行密钥并在本机保存

1. 打开 [Platform API keys](https://platform.openai.com/settings/organization/api-keys)，为这个隧道创建独立的运行密钥。密钥所属身份需要 Tunnels Read + Use；不要使用组织管理员密钥。
2. 双击项目根目录的 **Configure-ChatGPT.cmd**。
3. 第一栏填 Tunnel ID，第二栏填运行 API key。
4. 第三栏默认 `http://127.0.0.1:7897`，这是本机当前代理。能直连时可留空。
5. 点击 **Save locally**。密钥用 Windows DPAPI 加密，只保存在当前 Windows 用户的私有目录。

配置位置：`%LOCALAPPDATA%\X14-Plus-Project-Bridge`。该目录已限制为当前用户和 SYSTEM；不在项目源代码内。

本服务本身不调用模型推理 API。运行密钥用于官方隧道，不能据此推断隧道费用或将 ChatGPT 订阅视为 API 余额；以账号页面实际政策为准。

## 第四步：启动并检查

1. 双击 **Start-Bridge.cmd**。它启动本地服务，有隧道配置时再启动官方客户端。
2. 双击 **Check-Tunnel.cmd** 检查配置、网络和账号权限。
3. 双击 **Check-Bridge.cmd** 查看本地健康和隧道就绪情况。
4. 隧道运行时，可打开 [本机隧道状态页](http://127.0.0.1:18742/ui)。就绪状态通过后再去 ChatGPT 扫描工具。

本地 MCP 监听 `127.0.0.1:18741`，需要本机随机令牌；官方客户端自动带上该令牌。不要把本机 HTTP 地址直接填到 ChatGPT 的公网 URL 栏，也不要将这个服务直接发布到公网。

## 第五步：在 ChatGPT 创建应用

在 ChatGPT 创建自定义应用，填写：

| 字段 | 内容 |
| --- | --- |
| 名称 | X14-Plus Project Bridge |
| 描述 | 读取、搜索和修改 X14-Plus 本地与 SSH 项目，执行任务并查看结果。 |
| 连接类型 | Tunnel |
| Tunnel | 选择或粘贴第二步取得的 ID |

这是私人隧道连接，访问控制依赖官方隧道的账号/工作区授权；本机额外令牌由客户端管理。若界面要求选择应用认证方式，当前版本没有实现面向多用户的 OAuth 登录。仅在已确认私人 Tunnel 的情况下使用无需额外应用登录的选项。不要分享隧道给不应获得项目执行权限的账号。

保持客户端运行，扫描工具；预期看到 **12 个工具**。创建后，在新聊天中选择这个应用。工具定义更新后，需要刷新应用工具列表。

## 第六步：网页验收

只读、本地文件闭环、SSH 远端文件闭环、远程命令和代理联网均已于 2026-09-21 通过；下面只需完成关闭 Codex 后的独立运行验收。

先发送：

> 使用 X14-Plus Project Bridge，调用 bridge_status 和 list_projects。告诉我机器名、项目列表和实际调用结果。

预期有三个项目：`bridge`、`knowin`、`volcengine-cszy`。

然后发送：

> 在 bridge 项目中读取 README.md。新建 tmp/web-acceptance.txt，内容为“网页读写测试成功”。再次读取验证，然后通过 restore_change 撤回这次新建。所有写入使用唯一 operation_id。

再测试远端：

> 在 volcengine-cszy 项目中，通过工具在 tmp/web-acceptance.txt 完成同样的新建、读取与恢复测试。启动一个输出 42 的 Python 任务，并查询实际退出码与输出。

当前双击 `Start-Independent-Bridge.cmd`，确认 Bridge 健康、Tunnel HTTP 200、认证 MCP 验证 PASS，再从网页复测。SSH 联网代理按用户接受的方案继续依靠 Codex 的远程连接；该 CMD 不再额外启动 SSH 代理。

## 日常使用

### 更换即将到期的运行密钥

30 天不是本服务要求的期限。可以按平台提供的选项选择更长的有效期；到期后更换密钥，不需要重新创建隧道、ChatGPT 插件或项目配置。

1. 在 Platform 创建同等 Tunnels 运行权限的新密钥，先保留旧密钥。
2. 双击根目录 `Replace-API-Key.cmd`，只粘贴新密钥。现有 Tunnel ID 和代理自动显示且不可修改。
3. 保存时加密替换密钥，保留一份 DPAPI 加密的旧版本，并重新启动本项目登记的隧道连接。本地项目服务和后台任务不因此停止。
4. 运行 `Check-Tunnel.cmd` 并在 ChatGPT 成功调用一次工具，确认新密钥可用后再去 Platform 撤销旧密钥。

更换会短暂中断云端连接。保存成功不等于新密钥权限验证成功；若失败，重新运行更换入口填回仍有效的旧密钥即可。服务不会自动向 OpenAI 申请新密钥。当前更换入口已完成语法检查，真实密钥轮换需首次接入后实测。

- **Start-Bridge.cmd**：启动。已经健康运行时不重复启动。
- **Stop-Bridge.cmd**：只停止本项目登记并核对启动时间的连接进程；已经独立启动的任务需用 `cancel_job` 管理。
- **Check-Bridge.cmd**：状态。
- **Check-Tunnel.cmd**：官方客户端诊断。
- **Configure-ChatGPT.cmd**：配置账号。运行期间修改后需停止、重新启动。

默认不启用登录自启动。需要时可运行 `scripts/Manage-Bridge.ps1 -Action EnableLoginStart`；撤销用 `DisableLoginStart`。登录启动会同时尝试启动 Bridge、Tunnel 和使用现有 Host 配置的普通 SSH 代理。它是当前用户登录后启动，不承诺未登录运行；重启验收尚待实际进行。

## 远端代理

SSH 文件工具不需要远端外网，也不创建重复转发。联网任务可设置 `use_proxy=true`，使用远端 `127.0.0.1:19081`。

现有 SSH Host 配置保持不变，目前保持 Codex 的远程连接维持转发。高级手动入口 `scripts/Manage-Bridge.ps1 -Action StartProxy` 保留，但不由默认启动器调用，且不会抢占已有端口。

## 能力和限制

- 文件工具支持 UTF-8/UTF-8 BOM、中文、空格、CRLF；二进制及其他编码通过文件工具明确拒绝。命令工具可按具体需求处理这些格式。
- 搜索为本地执行的有界文本扫描；目前未引入语义索引。大目录应先选子目录，避免对整片共享存储反复扫描。
- `start_job` 是真实 PowerShell/bash 执行权限，能按服务账户权限操作项目之外的位置。项目 cwd 和文件工具边界不是 shell 沙箱。
- 目录穿越、符号链接/junction、常见凭据目录由文件接口拒绝；同账号外部程序并发改动路径的极端竞态，不构成操作系统隔离保证。
- 编辑前校验 SHA256；修改记录支持恢复。多文件操作不是完整文件系统事务，中断时可能要求人工查看恢复记录。
- 任务输出最多保存 8 MiB；单文件最多 2 MiB；长任务超时可指定到 24 小时。日志按字节分页。
- 任务和修改记录持久保存，尚未自动清理；配置目录需要按使用量维护。服务重启不代表任务自动重跑，失去心跳时显示 unknown。
- 没有实现桌面截图、键鼠工具；当前“电脑控制”通过文件和主机命令完成。
- 不继承 Codex 聊天历史、配额或内部工具。服务代码不调用 Codex；实际部署、网络条件及独立运行边界以文档 06 为准。

# 工具与实施计划

以下保留原始接口设计和验收要求。12 个工具现已实现；具体能力、测试和未完成项见 [实施与验收记录](05-实施与验收记录.md)。

## 1. 技术路线

初选 TypeScript + 官方 MCP SDK，使用 Streamable HTTP；远程批处理程序优先选择服务器已存在的 Python 运行时。具体版本在实现时核查、锁定并测试。OpenAI 文档列出了 TypeScript 和 Python SDK。[官方构建说明](https://developers.openai.com/plugins/build/mcp-server)

本地使用系统 OpenSSH，优先复用 `.ssh/config` 和 known_hosts；不在工具参数里允许任意主机地址、任意 SSH 选项或私钥内容。远程执行传递结构化输入，避免把模型生成参数直接拼接为 shell 字符串。

Bridge 运行时使用自己的项目登记表，不向 Codex 查询项目，也不借用 Codex 附带的可执行文件。当前项目列表只用于这次规划定位。

## 2. 最小工具集

工具名称允许实现时微调。所有项目操作都要求 project_id；返回中包含 machine_id、target_id 和实际目标，避免在多台机器上误操作。

| 工具 | 关键输入 | 返回与行为 |
| --- | --- | --- |
| `bridge_status` | 可选 target_id | 机器身份、连接状态、功能版本、权限档案；各网络层独立报告 |
| `list_projects` | 分页游标 | 已授权项目的稳定 ID、显示名、目标主机、能力 |
| `project_context` | project_id、预算 | README、适用 AGENTS.md、目录摘要、语言与运行入口、Git 摘要；列明未读取范围 |
| `list_files` | project_id、glob、游标 | 分页路径和元数据；忽略构建产物，限制扫描范围 |
| `search_project` | project_id、查询、路径过滤、结果上限 | 路径、行号、匹配片段、截断标记与续查游标 |
| `read_files` | project_id、文件与行范围数组 | 批量内容、编码、换行、文件哈希；明确每项失败 |
| `apply_changes` | project_id、操作数组、旧哈希、operation_id | 新建/补丁等常规修改；返回前后哈希、差异及逐项状态 |
| `git_inspect` | project_id、status/diff/log、有限参数 | 当前分支、实际差异和变更范围；非 Git 项目明确返回不支持 |
| `start_job` | project_id、命令档案或已授权命令、cwd、超时、operation_id | 很快返回 job_id；实际任务转后台，记录权限及代理配置名称 |
| `get_job` | project_id、job_id、输出游标 | 运行状态、分段日志、退出码、开始与结束时间 |
| `cancel_job` | project_id、job_id | 只取消 Bridge 自己登记的任务，报告实际取消结果 |
| `restore_change` | project_id、change_id、当前哈希 | 基于修改记录恢复；若后来又有人修改，返回冲突 |

Git 提交、删除/移动文件、推送、主机进程管理及桌面工具按下一阶段分别增加，不能隐含在只读工具里。常规 Git 查询也要审查外部 diff/filter 等可执行配置的影响。

统一错误至少包括 `UNAUTHORIZED`、`PATH_OUT_OF_SCOPE`、`CONFLICT`、`TARGET_UNREACHABLE`、`PROXY_UNAVAILABLE`、`TIMEOUT`、`RESULT_TRUNCATED`，并说明是否可重试。远程网络中断后状态不明的写操作先查询 operation_id，不能直接重复。

## 3. 上下文效率

目标是以少量工具调用完成“定位 → 阅读 → 修改 → 验证”。不把全盘或整个项目压成一个巨大提示词。

1. 首次读项目摘要、README、适用的 AGENTS.md、依赖声明和 Git 状态。
2. 用路径、符号或全文搜索定位代码，批量读取相关文件片段。
3. 修改前确认文件版本；修改后返回实际差异并运行相关验证。
4. 保存本次任务的文件列表、修改记录、测试状态和待办，方便下一次对话显式续接。

搜索优先用独立安装的 ripgrep，远端缺少时提供受限范围的替代实现。对大目录使用分页和预算，特别避免对 GPFS 等共享存储进行不受限递归扫描。大型二进制、缓存、依赖目录和日志默认不进入摘要。

文件和摘要缓存标注时间及内容哈希，不把过期缓存当成当前状态。向量检索可后续评估，第一版不以它作为高效读代码的必要条件。

若以后增加 Codex 历史导入，应按用户指定项目和会话筛选；会话索引只用于定位，实际内容从对应会话记录读取，且排除认证文件。

## 4. 写入与任务持久化

- 单文件尽量使用同目录临时文件和原子替换，保留编码、换行与必要权限。
- 多文件修改在应用前完成路径、哈希和补丁校验；写入过程记账，失败可恢复。没有可靠事务机制前，不声称多文件修改绝对原子。
- 恢复记录不能仅依赖 Git，因为已登记的本地/远程工作区可能不是 Git 仓库。
- 任意命令任务具有副作用；超时、输出限额、取消策略、重试策略必须明确，不能标注为只读。
- 远端长任务需要独立于 SSH 短连接的任务记录、进程与日志管理。SSH 中断时返回 unknown/reconnecting 等实际状态；后续查询恢复，不重复启动训练或构建。
- 文件写入/执行的权限由服务端校验，MCP annotations 只是行为提示。[官方工具说明](https://developers.openai.com/plugins/plan/tools)

## 5. 阶段交付

### P0：账号与连接可行性

交付：接入路线的实测记录，以及只有 `bridge_status` 和一个只读测试文件工具的最小服务。

验证目标账号开发者模式、创建自定义连接入口、Tunnel 权限和工作区关联；确认官方客户端在本机的安装/运行方式及代理配置。先运行客户端诊断，再从实际 ChatGPT 网页调用，不能以本地工具测试替代网页验收。

若 Windows 客户端条件不满足，评估官方支持的运行环境；WSL 会改变 Windows 文件与凭据访问方式，不能未经评估直接替代。若账号没有 Tunnel，则验证带认证公网路线。两个入口都不可用时，明确报告账号条件阻塞，而非继续假定可接入。

### P1：本地读写闭环

交付：在本项目下专设测试目录完成搜索、批量读取、补丁、新建、差异、恢复和任务执行；有真实身份/权限验证、操作日志和冲突处理。

通过后再登记实际项目目录。专门测试中文路径、空格路径、CRLF、同时编辑、链接绕出目录和断连重试。

### P2：火山引擎闭环

交付：通过 SSH 完成指定测试子目录的读写、校验、运行和日志查询。

先仅使用纯文件操作验证 SSH；再单独验证联网命令的代理和转发生命周期。保持现有 Host 级转发；Bridge 要显示自己持有的连接、继承的转发及失败原因。远端辅助文件只放在已授权位置。

### P3：独立运行与高效上下文

交付：独立依赖、明确启动/停止入口、运行状态、日志轮换、缓存、任务恢复和多项目切换。

在 Codex 关闭后完成完整验收；验证关闭浏览器再回来查任务、SSH 断线、代理重启、电脑休眠/恢复以及用户登录后的启动行为。开机运行和登录运行是不同承诺，应按实际方案记录。

### P4：更广泛电脑控制

交付：单独的主机权限档案、进程控制，必要时加入浏览器/桌面工具。

不能以开放 shell 冒充已验证的 GUI 自动化；桌面工具必须单独检查可交互会话、截图传输、目标窗口和操作结果。涉及管理员环境时另外评估，不让所有项目服务默认提权。

## 6. 验收矩阵

| 场景 | 通过标准 |
| --- | --- |
| 网页读取本地文件 | 返回实际内容、路径、行号与哈希，和磁盘核对一致 |
| 网页修改本地文件 | 磁盘确有变化、差异正确、可恢复 |
| 冲突编辑 | 文件在读取后被修改，旧哈希写入被拒绝而非覆盖 |
| 远程读写 | 网页工具结果与服务器同一文件哈希一致 |
| Codex 完全退出 | 本地/远端读写和任务查询仍可用；不依赖 Codex 子进程或附带工具 |
| 代理依赖 | 远端纯文件操作与联网操作分别验证；不以 SSH 成功推断代理成功 |
| 转发冲突 | 清楚报告 19081 归属/冲突，不结束未知进程 |
| 长任务 | 返回 job_id；重连后同一任务可查，退出码准确 |
| 重试 | 同一 operation_id 不造成重复补丁或重复任务 |
| 目录限制 | 文件接口拒绝绝对路径、穿越与符号链接/junction 绕出 |
| 命令权限 | 明确显示实际执行账户；严格隔离档案有独立越界验证 |
| 认证失效 | 未授权/过期/错误范围请求不能执行操作 |
| 恢复 | 恢复记录存在；检测后续编辑，不覆盖无关新修改 |
| 多机器 | 每次操作可追溯 machine_id、target_id、project_id |

还需记录真实任务的调用次数、总耗时、返回数据量、修改正确率与失败恢复情况，再判断是否达到预期效率。

## 7. 后续目录结构建议

```text
X14-Plus-Project-Bridge/
  README.md
  docs/                 当前规划文档
  src/                  后续 MCP 服务与本地/SSH 适配器
  remote/               后续远程批处理与任务执行程序
  config/               脱敏配置示例与项目登记 schema
  scripts/              明确可见的启动、停止、状态检查入口
  tests/                工具契约、权限、冲突与连接验收
```

实际凭据与运行数据位置在部署时确定，采用用户私有位置和合适文件权限；不把凭据混入上述源代码目录。本轮只创建 README 和 docs。

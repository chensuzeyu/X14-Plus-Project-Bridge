# 多模态与文件直传方案

更新：2026-09-21。状态：设计与隔离协议实验；后续已增加固定样本 vision_probe，见 [网页识图实验操作](09-网页识图实验操作.md)。通用多模态工具尚未实现，网页识图待验收。

## 范围与原则

按用户要求，移除上一轮提出的 GitHub 中转阶段。本方案不通过 GitHub 或其他第三方网盘中转文件。优先复用现有 Bridge、官方 Tunnel 和本地/SSH 执行能力；不新增模型 API 依赖。

目标分为三个独立方向：项目内容送给模型看；网页附件传入项目；项目文件进入网页原生文件分析环境。三个方向必须分别验收，不能把其中一个成功当成全部成功。

## 推荐路径与优先级

| 优先级 | 路径 | 用途 | 当前判断 |
| --- | --- | --- | --- |
| P0 | 项目图片 → Bridge → MCP image → 网页 GPT | 看截图、图表、设计图 | 最短路径，优先网页实测 |
| P1 | 网页附件 → fileParams → Bridge 下载 → 项目文件 | 把用户上传的文件送到本地/远端 | 官方有接口；账号和 Tunnel 待测 |
| P1 | 完整文件 → 本地/远端分析 → 文本结果与图片 → GPT | 表格计算、文档解析、大数据分析 | 可复用现有任务能力，图像出口需补齐 |
| P2 | 项目小文件 → MCP resource/blob 或 resource_link → 网页 | 探测原始文件交付和原生分析 | 协议支持不代表网页会下载或送入分析环境 |
| P3 | 插件文件界面 → 官方文件 API | 用户选择文件、下载产物、查看预览 | 在 P0/P1 之后按需建设；先检测接口是否可用 |

## A. 直接视觉输入

新增 preview_image(project_id, path, max_edge, crop?)。读取项目内图片，返回标准 image 内容块及简短元数据；不要把 Base64 写进 text 或 structuredContent。图片数据只发送一次。

先支持 PNG/JPEG，再按解码器能力增加其他格式。以文件真实类型和解码结果判定，限制像素量、字节数和处理时间。原文件保持不变。

默认返回预览，细节问题再取局部高清裁剪。初始工程预算建议单张预览不超过 1 MiB、每次不超过两张；这只是实验起点，不是 OpenAI 官方限制。按 SHA-256、页码、裁剪区域、渲染参数和渲染器版本缓存。

远端图片由 SSH 引擎读取/生成预览，经 Bridge 返回。首先测试本地，再测试 SSH，分别记录耗时和大小。现有 bridge.mjs 的约 500 万字符结果上限和 45 秒调度超时要纳入预算，超限应明确报错并建议缩图，不能截断图片。server.mjs 的 4 MiB 是请求体上限，不能误当成图片响应上限。

PDF/PPT 后续增加 inspect_artifact 与 preview_document：先给页数和索引，再按页渲染图片；图表和布局通过图片理解，文字通过有页码的文本提取。长文档按任务覆盖页面，不默认把所有页面一次送入上下文。

## B. 网页附件传入项目

新增 import_chat_file(project_id, destination, file, operation_id)。file 参数通过 _meta["openai/fileParams"] 声明，包含 download_url、file_id，以及可选的 mime_type、file_name。官方要求四个字段均在 schema 中声明，仅前两个必填。

流程：宿主注入附件引用 → Bridge 下载到受控暂存目录 → 检查长度、真实类型与哈希 → 原子保存 → 返回 artifact_id、大小、哈希和保存位置。目标文件名由受控参数决定，不能直接信任外部文件名；覆盖仍遵循现有哈希冲突保护。

下载器须限制 HTTPS、超时、重定向次数和最大字节数；每次连接/重定向检查目标地址，阻止本地、私网和元数据地址，正式实现避免 DNS 重绑定。只在实际观察到官方下载主机后建立可维护的准入规则，不接受任意用户 URL 充当附件。带签名的下载地址不得进入日志和持久清单。

文件保存权限沿用项目范围、write 配置、链接排除规则；远端通过明确的二进制传输保存。幂等以 operation_id 和内容哈希判断，不能以可能过期/轮换的下载 URL 判断重复。

## C. 分析闭环

网页 GPT 选择分析步骤，现有 start_job 在本地或远端读取完整文件，产出带来源的结果、图表和报告；get_job 返回任务状态和简短日志，新增产物接口交付图片与结果。

对表格记录工作表、行数、字段、缺失值、筛选条件和源文件哈希；统计计算使用完整数据，抽样仅用于预览。大文件保留在数据所在机器，只传模型需要的结果和图像。

产物清单建议包含 artifact_id、project_id、相对路径、真实 MIME、大小、SHA-256、生成任务、源文件哈希、创建时间。内部路径和临时凭据不作为可点击的云端下载地址。

明确区分：这种方式是网页 GPT 指挥本地计算，并不代表原始文件进入了 ChatGPT 的原生数据分析环境。

## D. 原始文件交付实验与备选

依次实验 embedded resource/blob 和 resource_link + resources/read，观察网页是否能取回真实字节、是否能进一步送入原生分析工具。不能把 resource_link 可显示、SDK 客户端可取回，或模型能复述样本，记作原生分析成功。

如网页不消费资源，保留 A/C 作为自动路径；用户在确实需要原生网页分析时可直接上传本地文件。远端文件可先由 Bridge 同步到本地再上传，这条路有手动步骤。

插件界面的 uploadFile/selectFiles/getFileDownloadUrl 可作为后续候选，但官方描述主要针对用户选择的文件和已授权文件；不能假设服务端可随意上传项目文件、自动附加到当前对话。界面能显示图片也不等于模型已接收图片。

本轮不建设公网文件服务。现有官方 Tunnel 的 MCP 可达性不能证明任意 /files 下载路由可由浏览器或分析环境访问；若将来确需自有 HTTPS 直传，应作为独立方案验证认证、短期链接、下载路径和生命周期，而不是绕过现有认证。

## 实施顺序和停止条件

1. 隔离协议实验：测试 image、fileParams、resource/blob、resource_link；不重启在线 Bridge。
2. 固定合成样本的网页实验工具：刷新网页工具列表，先测直接看图和真实附件引用。失败时记录发生在发现、Tunnel、内容类型还是模型使用环节。
3. 图片通路通过后，建设生产 preview_image、裁剪缓存、PDF 分页及 SSH 通路。
4. 真实附件下载通过后，建设带冲突保护、幂等和下载防护的 import_chat_file。
5. 验证完整 CSV/Excel 分析与图表回传，再做原始文件进入网页分析环境的 P2 实验。
6. 只有目标账号证明需要且支持界面文件 API 时，才加入 P3 界面。

不改造既有工具让其暗中返回图片；使用明确的新工具和可撤回的实验开关。记录每一步的能力，不因为某个实验失败就改用第三方中转。

## 验收标准

| 实验 | 样本与判定 | 不足以证明成功的现象 |
| --- | --- | --- |
| 视觉 | 随机图形、颜色、相对位置；文件名和文本不泄露答案；模型回答后才比对真值 | 图片出现在界面、模型读到描述 |
| 高清局部 | 预览中无法辨认的小字，裁剪后可辨认；记录两次大小和耗时 | 直接提供 OCR 答案 |
| PDF | 混合文字、图表、扫描页；答案附页码 | 只提取文字 |
| 附件导入 | 网页上传合成文件，项目落盘 SHA-256 与原始值一致；重复请求不重复覆盖 | 仅收到 file_id 或 URL |
| 数据分析 | 全量数据的预设统计答案，含中文、空值和异常值；输出图表可见 | 仅对前几行求和 |
| 原生网页分析 | 取得原始文件、执行全量计算、返回新产物，并保留实际工具证据 | 本地任务执行成功 |

## 本轮实验记录

2026-09-21 实际运行 scripts/probe-multimodal.mjs，使用当前安装的 MCP SDK，通过临时回环 Streamable HTTP 服务完成 5 项检查：fileParams 元数据及 schema 保留、image 类型及字节一致、合成文件引用被接收、embedded resource 字节一致、resource_link 后显式 resources/read 字节一致，全部通过。样本为 68 字节 PNG 与 24 字节 CSV，只用于传输协议验证。

报告：tmp/multimodal-probe/result.json。脚本退出后关闭临时监听；不读取项目私有文件，不下载 URL，不修改或重启在线服务。复现：node scripts/probe-multimodal.mjs。

现有连接器 bridge_status 调用成功，证明本会话可调用在线 Bridge 文本工具，不证明多模态支持。浏览器自动化访问 ChatGPT 页面和随后读取页面均超时，因此本轮没有网页模型识图、真实附件注入/下载、资源自动读取或原生数据分析验收结果。没有据此判定网页不支持这些能力。

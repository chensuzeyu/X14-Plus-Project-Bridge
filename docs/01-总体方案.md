# 总体方案

日期：2026-09-21。此文件保留最初设计；当前实现状态和偏差以 [实施与验收记录](05-实施与验收记录.md) 为准。

## 1. 需求与边界

目标是在任意可登录目标 ChatGPT 账号的浏览器中，对 X14-Plus 指定目录和火山引擎指定目录完成：了解项目、搜索代码、读取上下文、编辑文件、运行测试、查看差异、跟踪长任务。整个执行链不调用 Codex CLI、Codex App Server，也不要求 Codex 桌面应用保持运行。

“Codex 项目”首先是磁盘上的目录，可以由其他程序直接操作。已有 Codex 聊天记录、任务列表、记忆、工具和权限不会随目录自动进入 ChatGPT。若需要沿用历史，应另建明确的上下文导入功能；不能把整个 `.codex` 目录作为默认可读资料。

“全权控制”分为两类能力，规划均予以覆盖：

| 能力层 | 内容 | 计划 |
| --- | --- | --- |
| 项目操作 | 指定目录检索、文件增改、差异、Git、测试与构建 | 首个完整版本 |
| 主机操作 | 更广范围目录、任意命令、进程管理 | 独立可开启的主机权限档案 |
| 桌面操作 | 截图、键鼠、窗口与浏览器操作 | 后续专用工具；MCP 不自动提供这些能力 |

即使开放主机命令，权限上限也是服务运行账户的 Windows/Linux 权限。管理员权限、桌面交互会话和操作系统安全提示仍有独立条件。不能把安装插件等同于获得系统管理员权限。

功能目标可以接近 Codex 的常用项目工作流，但上下文容量、连续执行、工具选择、确认行为仍受 ChatGPT 产品与账号限制；“效果完全等同 Codex”必须通过真实任务对照验证。

## 2. 名称与机器身份

- 用户显示名：**X14-Plus Project Bridge**。
- 软件标识：`x14-plus-project-bridge`。
- 用户指定机器别名：`X14-Plus`。
- 当前系统返回主机名：`SCHEN`。保留二者映射，不更改 Windows 主机名。
- 正式运行时生成独立 `machine_id`；不同电脑使用不同机器 ID、配置和凭据。显示名称不充当认证凭据。
- 火山引擎目标名：`volcengine-cszy`；SSH Host：`volcengine-cszy_1-L20`。

## 3. 哪些软件运行在哪里

| 组件 | 位置 | 作用 | 是否必须 |
| --- | --- | --- | --- |
| ChatGPT 网页版及自定义 MCP 连接 | 浏览器与 OpenAI 云端 | 理解需求，调用工具，解释结果 | 必须 |
| Project Bridge MCP 服务 | X14-Plus | 目录授权、检索、修改、任务执行、SSH 调度 | 必须 |
| 官方 tunnel-client | X14-Plus | 将私有 MCP 服务接入 OpenAI | 首选方案必须 |
| OpenSSH、Git、独立搜索工具 | X14-Plus | 执行实际项目操作 | 按功能需要 |
| SSH 服务、项目运行环境 | 火山引擎 | 远端文件和进程操作 | 远程功能必须 |
| 小型远程执行程序 | 火山引擎项目专用位置 | 批量读写、校验、长任务日志 | 拟采用；不是模型或 Codex |
| 现有本地网络代理 | X14-Plus | 本机出站及远端命令联网 | 按网络环境需要 |

MCP 是模型调用工具的协议；它不会替你运行服务。这里真正“动手”的是 Project Bridge。电脑关机、休眠、断网，或 MCP/连接客户端退出时，云端不能继续访问本地目录。

在拟议架构中，关闭网页不必结束已经启动的持久任务，但不会因此自动产生持续的模型决策。用户重新打开对话后查询任务状态；主动通知或持续代理循环属于另外的实现范围。

## 4. 官方接入路线

### 4.1 首选：官方 Secure MCP Tunnel

OpenAI 文档提供私有 MCP 的出站隧道连接，适用于开发者模式；需要 tunnel_id、运行时 API key、Platform 隧道权限及目标 ChatGPT 工作区关联。它不要求本机开放公网入站端口。[官方说明](https://developers.openai.com/api/docs/guides/secure-mcp-tunnels)

本项目拟采用本机回环 HTTP MCP 接口，由 tunnel-client 转接。服务端口在部署时选择并检查冲突，不复用现有代理端口。HTTP 便于独立检查和重启；若实际客户端的 stdio 集成更稳定，可以替换传输适配层。

接入次序：先确认账号入口与权限，再安装适合本机的官方客户端，运行诊断，用一个只读测试工具验证网页调用，最后启用实际项目能力。

这是新项目接入 OpenAI 的传输组件，和“远端服务器通过 SSH 借用本地代理”是不同链路。无需为此重新设计已有火山引擎代理转发。

### 4.2 备选：公网 HTTPS MCP + OAuth

如果目标账号无法使用 Tunnel，但可以创建自定义 MCP 连接，可将 MCP 的 `/mcp` 暴露为稳定、可访问的 HTTPS 入口，并配置 OAuth。OpenAI 的连接文档列出了公网 HTTPS 和 Secure MCP Tunnel 两条接入路径。[连接文档](https://developers.openai.com/plugins/deploy/connect-chatgpt)

公网入口可由反向代理或受控中继实现；具体供应商暂不选定。此方案增加域名、TLS、入口运维和认证成本，应在首选方案不可用后再评估。公网 `localhost`、家庭内网地址、仅自己设备可访问的私网域名，都不能直接假定 OpenAI 云端可达。

若开发者模式本身不可用，单纯换公网入口不能解除产品权限限制。

### 4.3 插件形态

先做“只有 MCP 的私有连接”，工具稳定后再包装项目工作流说明，必要时补充差异查看界面。官方允许无自定义 UI 的 MCP 插件。[插件架构](https://developers.openai.com/plugins/concepts/plugins)

本需求是个人机器接入，不以公共目录上架为目标。官方私有 Tunnel 不适用于公开插件提交或分发。网页连接与本地 Codex 插件目录是两个部署环节；在本地放置 manifest 文件，不会自动部署一个可由网页版调用的服务。

## 5. 火山引擎与网络代理

### 5.1 项目数据通道

```text
ChatGPT → 官方 MCP 隧道 → X14-Plus Project Bridge
                                  ↓ SSH
                       volcengine-cszy_1-L20
                                  ↓
                    /Knowin/sim/chensuzeyu/指定子项目
```

远端纯文件读写只要求 X14-Plus 到服务器 SSH 可达，不要求服务器能连接 OpenAI。模型在 OpenAI 云端，服务器只执行工具操作。这可以减少项目操作对服务器外网连通性的依赖。

当前 Codex 已登记 `volcengine-cszy` 根路径为 `/Knowin/sim/chensuzeyu`，但本次未登录服务器验证目录及运行环境。部署时按实际子项目登记，不能把一个根目录等同于单一 Git 仓库。

### 5.2 远端命令联网通道

```text
远程 pip / git / 下载程序（配置了代理时）
  → 远端 127.0.0.1:19081
  → SSH RemoteForward
  → X14-Plus 127.0.0.1:7897
  → 外部服务
```

当前 SSH 配置确有 `RemoteForward 127.0.0.1:19081 127.0.0.1:7897`；本地 7897 有监听。配置存在不代表远端端口当前有效，也不证明某个实际进程使用了代理。

不运行 Codex 以后，不能依赖 Codex 所持有的 SSH 连接维持转发。拟由 Bridge 按需建立并持有一个使用现有 Host 配置的 OpenSSH 会话，显式报告连接状态与转发是否成功；远端长任务需要联网时，会话应持续存在。

保留 Host 级转发配置，不迁移到隐藏守护脚本，不自动切换代理节点。已有进程可能占用 19081，实施时先识别转发归属；不能杀死未知进程、盲目再占用端口或把冲突误报为 SSH 完全不可用。

纯文件会话可在明确不需要转发时禁用继承的 forwarding；需要联网的执行会话则必须先验证转发，并校验实际子进程的代理环境。已有转发可达时也要标注其生命周期是否仍依赖 Codex。

不要依赖交互式 shell 自动加载代理。为远端任务传入明确的代理配置和适当 NO_PROXY，按实际程序验证；并非所有应用都会服从相同的环境变量。MCP 服务的回环连接不应误走外网代理。

## 6. 授权与“全权”的实际含义

为达到高效编辑，项目档案可预先允许指定目录内的常规读取、编辑、构建和测试，避免 Bridge 自己再增加每次编辑的确认窗口；ChatGPT 自身的确认规则仍须遵守，不能承诺完全无确认。

| 档案 | 允许能力 | 边界 |
| --- | --- | --- |
| 项目文件 | 枚举、搜索、读取、补丁、新建文件 | 服务端限定已登记项目根目录 |
| 项目执行 | 测试、构建、脚本、任务日志 | 进程隔离或账户权限决定真实边界 |
| 主机操作 | 任意命令、更广目录、进程管理 | 接近服务账户的全部权限 |

关键区别：把命令的工作目录设为项目目录，不构成沙箱。任意 shell、Python、测试脚本或依赖安装程序仍可能访问账户能访问的其他文件；仅有路径白名单保护不了命令执行。需要严格“只操作项目”时，必须增加操作系统权限或容器隔离；需要主机级灵活性时，应如实展示扩大后的能力。

本项目采用的工程要求：

- 文件接口按 project_id 和相对路径操作，检查实际解析路径、符号链接、Windows junction、UNC 和路径穿越；这些是文件接口边界，不冒充 shell 隔离。
- 写入带旧内容哈希、操作 ID 与冲突检测；保留可恢复版本，返回实际差异。重试不重复执行同一写操作。
- SSH 私钥留在本机；隧道密钥与业务凭据分别保存。认证不靠机器名字或难猜 URL。
- 私有隧道限制允许使用的组织/工作区。业务端仍须核实调用者身份或明确单用户信任边界；写权限不能在认证设计不清时开放。
- 公网模式采用 OAuth 授权码与 PKCE、校验 token 的 issuer/audience/有效期/scope。[官方认证文档](https://developers.openai.com/plugins/build/auth)
- 不默认返回 `.env`、私钥、认证数据库或全部历史会话。日志记录操作元数据并脱敏；工具结果中的源码会进入云端模型上下文，私有隧道不等于源码从未离开电脑。
- 项目里的指令性文字按项目资料处理，不能覆盖服务端授权；工具 annotations 准确反映副作用。[工具设计文档](https://developers.openai.com/plugins/plan/tools)

具体目录和主机档案作为部署配置确定；本次创建规划文档不等于已开放这些权限。

## 7. 成本和可用性

Bridge 本身可以只做工具执行，不调用模型 API；用户交互仍发生在 ChatGPT。官方隧道需要运行时 API key，这与 ChatGPT 订阅、模型 API 用量是不同事项。当前文档核验不足以给出隧道收费或账号可用性承诺，实施前检查目标组织页面和计费说明。

主要运行依赖是：X14-Plus 开机且不休眠、Bridge 与连接客户端存活、本机出口可达、SSH 可达、所需运行环境存在。后续可做登录启动和故障状态显示；要宣称“关掉 Codex 后稳定工作”，必须在对应条件下完成验收。
